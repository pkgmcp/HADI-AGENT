Architecture معماری HADI

HADI follows clean architecture with strict separation of concerns. The system is organized into distinct layers, each with a single responsibility.

Key Principles / اصول کلیدی

🎯 Single Responsibility

Each class has one clear purpose. Controllers handle HTTP, Services contain logic, DTOs transfer data.

🔌 Dependency Inversion

High-level modules depend on abstractions (Interfaces), not concrete implementations.

📦 Immutable DTOs

All Data Transfer Objects are readonly. Data flows one direction through the system.

🔄 Provider Agnostic

AI providers are interchangeable via the AIProviderInterface. Swap providers without code changes.

🧩 Modular Services

Each service is independently testable and replaceable. Clear boundaries between MCP, Agents, and Workflows.

📊 Observable by Default

Token usage, costs, latency — all tracked automatically. No extra instrumentation needed.
